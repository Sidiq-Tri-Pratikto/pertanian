# Web Standards

Next.js App Router, React, TypeScript, one responsive web client for desktop and phone.

## Layout

```
applications/<web>/
├── src/app/              # routes only: read the session, call a view, nothing else
├── src/api/              # typed client, server fetch, failure parsing, generated contract
├── src/components/tr/    # ports of the TemuRiset Design System, same names and props as window.TR
├── src/design/           # design-system stylesheets copied verbatim, plus app.css
├── src/features/         # feature logic, registry, hooks
├── src/views/            # screens composed from components; testable without Next
└── tests/                # unit, page, accessibility and drift tests
```

## Code

- TypeScript strict. No `any`; narrow `unknown` at boundaries.
- Import through `@/`. Server-only modules never reach a client component.
- Mark a component `'use client'` only when it needs state, effects or browser events.
- Every `NEXT_PUBLIC_*` value ships to browsers: never put a secret there.
- `src/api/schema.generated.ts` comes from `make generate-api`; `src/design/tokens.css` and `bundle.css` come from `make design`. Never edit either.
- Port a design-system component when a feature first needs it. Keep its class names and props, and record any deviation in `docs/roadmap/architecture.md`.

## Server contract

- Browsers call only the web origin. `/api/v1` is forwarded to the service, so cookies stay first-party.
- The service owns rules, matching, permissions, money and consent. The client formats what it receives and never parses money into floats.
- Branch on the public error `code`, never on message text. Show `message` and the reference ID.
- Honor `recovery`: stop retrying when `retryable` is false or `max_attempts` is reached.
- Every request has a timeout. Consequential mutations send `Idempotency-Key` and `expected_version`.

## Screens

- Every screen has loading, success, failure, empty and permission-denied states. A failure keeps entered values and the last confirmed content.
- One primary action per task region, named by its effect. Show who acts next with `NextStep`.
- Show the acting party before send, decide, share and confirm.
- Invalid submission focuses a linked error summary. Status changes are announced without moving focus.
- Targets are at least 24 × 24 CSS px, primary controls 44 px. Text scales to 200% and reflows at 320 CSS px.

## Testing

- Vitest with jsdom and Testing Library. `make check` enforces 80% line coverage.
- Query by role and visible text. Assert behavior, including failure, retry and denied paths.
- Run axe on each new view. Contrast, focus visibility and reflow need a real browser (spec 003).
