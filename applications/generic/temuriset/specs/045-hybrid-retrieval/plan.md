# Implementation Plan: Hybrid retrieval and reranking (gated)

**Branch** `045-hybrid-retrieval` | **Date** 2026-11-05 | **Spec** [spec.md](spec.md)

## Summary

Deliver a default-off development experiment through the existing matching routes and an offline evaluation command. Compare the shipped `lexical-rules@1` keyword-overlap baseline with dense+rules, BM25/dense hybrid+rules and hybrid+rerank+rules. The text/trigram discovery query and the Spec 039 timing benchmark retain their current purposes.

## Architecture and constitution check

- **Authority and backward compatibility.** Use `MatchingService.source_of`, `IntakeService.active_targets` and the existing acting-party, ownership and visibility policies before looking up an experiment. Keep the original lexical path unchanged, including when a local profile falls back. Use the existing idempotency and owned-run read, with no new API route or database migration. Existing runs without retrieval provenance remain readable.
- **Local trust boundary.** A developer-only producer takes the committed fixture, calls a literal-loopback model double, validates the outputs and publishes a bounded, versioned local artifact. An explicit development/demo profile loads and validates the optional artifact once before serving matches. The request path reads the immutable in-memory snapshot; it performs no file I/O. Restart to replace the artifact. It has no model network calls during request or write transactions. A missing or invalid artifact keeps the API available and produces a safe fallback on attempted runs. Reject contradictory configuration and production enablement at startup. Never send database-derived text, identifiers, evidence or documents to the relay. Use only canonical fixture text, opaque per-call positions, pinned model identity/revision/tokenizer/truncation/template, and a strict endpoint contract. Disable redirects, proxy inheritance and implicit retries. Bound total time, request and response sizes, dimensions and counts, and reject nonfinite, zero-norm, unrecognized or mismatched outputs. Store or log no raw payload, vectors, provider response, paths, endpoints or credentials in match runs or diagnostics.
- **Scope of precomputed outputs.** Validate the artifact against the exact fixture version and profile pins. Bind it to the relevant curated source and target projections and expected catalog slice; select only after applying the live matching policy. Use a deterministic mapping from authorized projection values or a pinned synthetic test seed to fixture keys. Do not infer that user data is synthetic from the environment alone. A changed, incomplete or unrecognized slice uses the full lexical fallback instead of guessing or filtering out other visible targets. Keep partner-only requirements and the authoritative rows out of inference data. Preserve all original checks in the lexical path.
- **Pure ranking.** Score BM25 with a deterministic Unicode tokenizer and a versioned parameter set. L2-normalize validated dense vectors and score their exact dot products over the bounded authorized pool. Apply stable one-based RRF with k = 60; an absent rank contributes zero. Each channel returns up to 50 items, and reranking operates on at most 30 fused candidates with stable handling of the untouched tail. Use separate, versioned relevance admission for dense, hybrid and reranked modes. Freeze thresholds before held-out evaluation and reject ambiguous or missing signals conservatively. A validated empty result is an abstention. An unavailable or invalid experiment is a fallback.
- **Rule semantics.** Feed only admitted relevance evidence into the authoritative engine. Leave numeric fit, eligibility, readiness, row outcomes and source-backed explanations unchanged. Known mandatory submission FAIL never enters results; UNKNOWN remains provisional with its existing reason and action. Use eligibility, descending conservative lower fit, experimental rank and stable opportunity ID for experimental display, with up to five shown. Evaluate per target and do not convert valid results beyond the display cap into incompatibilities. Model output supplies no explanation or verified fact.
- **Storage and UI.** Reuse the existing match-run JSONB input snapshot for safe provenance, including requested/effective mode, version pins and a closed fallback reason. Expose it as an optional field for the existing owned response and preserve it on idempotent replay. Retain the existing target-version snapshot. Use the effective engine version. Render a concise Indonesian fallback note in S10 from structured metadata. Default registry and deployed manifest stay unchanged; a local experiment state must not be presented as deployed adapter availability.
- **Index boundary.** Use exact in-process dense scoring for the bounded synthetic experiment. The existing PostgreSQL environment has no installed pgvector extension. Keep the persistent pgvector index, its authorization and performance validation, and real multilingual model qualification in the separate production gate. The local comparison provides no pgvector latency or multilingual quality evidence.

## Evaluation contract

Use an immutable synthetic corpus with graded relevance, expected requirement outcomes and explanation support, and both new and established manager cohorts. Include no-result and low-confidence cases, related records, a useful no-overlap candidate, mandatory FAIL and UNKNOWN, and stable negative judgments. Assign connected components of related inventions/entities/requests/opportunities/near-duplicates to development or held-out groups. Validate that no group or linked item crosses the split; derive any tuning from development only. All modes use the same immutable input versions and judged target pool per query. The production study additionally requires permissioned real cases, two independent human reviews, preserved initial disagreements and an adjudicated record.

The command reports per-mode and per-split candidate recall before rules, precision over actual returns, precision@5 with a denominator of five where defined, nDCG@5 against the full judged ideal, hard-rule violations, UNKNOWN correctness, factual support, coverage/abstention, result counts, latency, cost status and new/established manager exposure. Publish denominators and counts for undefined aggregates. Report synthetic retrieval outcomes and local elapsed time as fixture evidence; report real-provider cost as unmeasured. Apply safety assertions separately from relevance metrics.

## Verification and rollout

1. Establish failing tests for the fixture, ranking, relay contract, normal matching, owner isolation, idempotent replay and fallback before implementation.
2. Run the frozen local evaluation, matching/API and web tests, regenerated contracts and project gates. Capture the command, artifact pins and results in `docs/roadmap/benchmarks.md`.
3. Record the separately reviewed real dataset and mode-specific gains, approved multilingual model and transport, scope/consent, persistent pgvector authorization and latency, cost and staging behavior before promoting a capability. Keep these tasks open after synthetic verification.
