## API and lifecycle

- `POST /imports/validate` stages a bounded raw `application/json` file and queues validation. The query carries `acting_party_id` and the optional `map_private_notes` choice. `GET /imports/{id}` reads distinct validation, preview and apply status and progress. Successful validation queues preview. The status route exposes a bounded page of preview rows once authorized.
- `POST /imports/{id}/apply` takes the run version and starts work only after successful preview. `POST /imports/{id}/cancel` takes the run version and stops pending work or prevents the next unit of work. The response states how many records committed before cancellation.
- `POST /exports` queues a bounded export of explicit resource references. `GET /exports/{id}` shows job status. `GET /exports/{id}/download` serves the result as a private JSON attachment with `Cache-Control: no-store` after fresh authorization.
- Each consequential POST includes the acting party and an idempotency key, and returns an operation ID. The first create uses a null expected version. Existing runs require their current version. The idempotency digest includes the upload bytes through their SHA-256 and the canonical request metadata. Job input and outbox events carry internal IDs.

## Import contract and concurrency

The v1 file envelope has `schema_version: 1`, `external_system`, source provenance and an `inventions` array. Every row has an `external_id` and provenance. A file may include one optional `partner_profile` row for the same managing party. Validate data against the JSON contract and reuse the portfolio request model for the accepted invention fields. Bound a file to 20 MiB and 2,000 rows, and keep preview pages to 100 rows or fewer. These product limits cover the 1,000-row acceptance scenario and keep requests and responses bounded.

Use a private staging key generated by the server. Default to title, summary, problem, solution, intended users, sector, stage, keywords and source-reported facts. Private field mappings must be selected explicitly by the requester and authorized for the destination by the API. Preserve omitted fields. Record source-reported relationship assertions with the external reference, separate from any operational relationship state. An organization name stays source text. A raw workspace ID grants no access. Reuse 016's `IntakeService.record_directory_profile` only for a first source-reported profile in the authorized acting context. An existing owner-confirmed profile is preserved and shown as a conflict. A repeat of the same applied source profile must not create another profile.

A preview pins the upload digest and destination versions, lists creates and updates, and identifies reviewed-fact or rights conflicts. Apply rechecks the compared version and protects reviewed facts and rights from both the current draft and published version. Skip unresolved conflicts. The owner can resolve them through the ordinary portfolio workflow and get a fresh preview. Create or update drafts via the portfolio service. Keep published versions immutable. Enforce unique external references and serialize the first upsert so two workers cannot create two inventions for one external key. Make retries and checkpoints idempotent.

## Export authorization and expiry

Own each job by requester account and managing party. Use live membership and the central policy at creation, worker execution, status and download. Keep an allowlist for exportable portfolio fields and exact resource dependencies, including a selected document version and its applicable grant. Use the same access checks as the document gateway. An export selection does not itself confer bulk access to an organization or permission to a private field.

Record dependencies with the result and recheck each immediately before streaming. Expire the result if a dependency or the requester's membership is revoked. Persist invalidation through denial and remove the private bytes through the existing retryable worker path. Deny unrelated callers without disclosing or invalidating another requester's result. An expired result cannot revive when permissions return. Use a 24-hour lifetime for temporary export results and apply the same expiry to abandoned import staging data. The JSON attachment is capped at 20 MiB and 100 explicitly selected resources. Document attachments use Base64 and carry their exact version. Reimporting an artifact skips attachments. Expire on access even if cleanup is late.
