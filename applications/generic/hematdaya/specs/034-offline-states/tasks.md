## Decisions from analysis

- The confirmed owner is the authenticated one-site demo principal. Attest on create/replay or owned site GET, bind the credential to a durable epoch, and fence before reset. A stored site ID alone never authorizes hydration.
- A restored asset draft opens without an asset detail response. An owned, fresh detail read must resolve match or divergence before a new PATCH can be explicitly authorized.
- Keep 027's verified status-first record separate from general drafts. The same key survives supported web reloads only for previously dispatched commits. First-workspace input adoption is allowed once. An adopted draft never crosses owners.
- Keep the resolved dates, cutoff, timezone, scope IDs and local scope epoch independent of the summary's data revision. 028 will supply the separate selection revision. 029 owns scope resolution UI.
- The app observes resets it initiates and revocations it learns from the API. Full disconnection limits it to prior attestation and known local expiry.
