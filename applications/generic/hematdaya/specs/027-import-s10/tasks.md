## Decisions resolved against the code

| ID | Decision | Why |
|---|---|---|
| D1 | Pick files with `expo-document-picker`, added with `npx expo install expo-document-picker` (SDK 58 pins `~58.0.4`). Call `getDocumentAsync({ type: '*/*', multiple: false, copyToCacheDirectory: true, base64: false })`. Never read the bytes in JavaScript: native uploads the picked `uri` as a `{ uri, name, type }` FormData part, and web uploads the returned `File`. Do not add `expo-file-system`. | S10, PRD §10.2 and UX-20 require file or paste, and React Native has no file input. The picker covers Android, iOS and web, where it builds an `<input type="file">` and returns `file` (measured from its web source). The API takes the file as multipart and decodes UTF-8 itself, so reading the file client-side would only copy 10 MiB into JS. `copyToCacheDirectory` keeps a stable `uri` that can be uploaded again for every re-preview, which some Android providers' `content://` URIs do not allow. `*/*` because some Android providers label `.csv` as `application/octet-stream`, which a narrower filter would grey out; the service judges the content. `expo-file-system` is already a transitive dependency of `expo` and is not imported. |
| D2 | Paste stays a full second path: a multiline `HDTextField` whose text is sent as the `text` part. A file and a paste are never sent together, and one never silently replaces the other (D16). | US1 scenario 2. The route answers `BAD_REQUEST` when both are sent (measured). Paste needs no native module, so it is also the fallback whenever the picker cannot be used. |
| D3 | Every request still has a timeout, but `apiRequest` gains a `timeoutMs` option. Preview uses `IMPORT_PREVIEW_TIMEOUT_MS = 120_000`, commit `IMPORT_COMMIT_TIMEOUT_MS = 60_000`, and every other call keeps `TIMEOUT_MS = 10_000`. | Measured on merged code over local HTTP: a 9,120,044-byte, 150,000-row preview took 8.94 s, before any network upload, and its commit 9.12 s. 026 measured 20.62 s for a counter commit. At 10 s a large preview fails on any real network, and a large commit always looks lost. 60 s is PRD §18's whole budget, and 120 s adds room for a 10 MiB upload on a slow link. These are engineering defaults, not phone measurements. |
| D4 | A preview has no idempotency key and cannot be recovered after a lost response, because nothing returns its ID. A lost or timed-out preview is reported as "not finished" with **Coba lagi** (a new POST with the same source and answers), and says that saved data did not change. | A preview writes only `imports` and `import_rows`, never a reading, and the service keeps the newest 5 uncommitted previews per site and purges the rest (measured: the sixth preview made the first `NOT_FOUND`). So a repeat is harmless, and a lost one is cleaned up. No API change is needed for this. |
| D5 | Commit keeps one intent `{ importId, key, acknowledge }` with `key = randomToken(16)` (22 base64url characters, inside `^[A-Za-z0-9_-]{22,128}$`). Any failure that is not a definite refusal, including `NETWORK_UNREACHABLE` from a timeout, `UNEXPECTED_RESPONSE` and any 5xx code, makes the state `unknown`. From `unknown` the only action is **Periksa status**, which calls `GET /imports/{id}` before anything is resent. No automatic resend, ever. | FR-004 and the handoff ("A timeout after commit must look up the existing operation/idempotency key before retrying"). Measured: a repeat with the same key answers `replayed: true`, and so does a new key on an import already committed. `apiRequest` turns every fetch failure, timeouts included, into `NETWORK_UNREACHABLE`, so the client cannot tell a timeout from a lost connection, and both are unknown. |
| D6 | Branch on `GET /imports/{id}` after an unknown commit: a non-null `result` shows the result as "sudah dikonfirmasi sebelumnya"; `status: previewed` offers **Kirim lagi** with the same intent; `expired` or `NOT_FOUND` lead to **Buat pratinjau baru**; a failed check stays `unknown` with that check's message and reference. | 026's handoff. The GET takes no lock, so `previewed` may also mean "still in flight": a resend with the same key waits on the site lock and replays, which is why it is safe. `NOT_FOUND` can only mean an uncommitted preview that was purged, because purges skip committed imports. |
| D7 | Every commit and preview failure branches on `code` alone, per the Error behaviour table below. `details[].msg` is shown where it exists and the reference ID always. | Rule 008, rule 009 and the brief. Messages are never parsed. |
| D8 | `ApiError` gains `details: ErrorDetail[]` (default `[]`), read by `readFailure` from `error.details` when each item has an array `loc` and string `msg` and `type`. Anything else is dropped. | `readFailure` discards `details` today, and `IMPORT_INVALID`, `IMPORT_TOO_LARGE`, `IMPORT_STALE`, `IMPORT_ACK_REQUIRED` and `VALIDATION_FAILED` carry their specifics only there (measured). `ErrorBody.details` is already in the generated contract, so no contract change. |
| D9 | Preview requests always send `mapping` as JSON text of the draft's answers, typed by a hand-written `ImportAnswers` in `client.ts` that mirrors `ImportMappingRequest` (`value_kind`, `power_meaning`, `timezone_confirmed`, `interval_minutes`, `asset_map`, `scope`). | The multipart body is documented by `openapi_extra` with `mapping` as a string, so `schema.generated.ts` has no `ImportMappingRequest`. `{}` is valid for a first preview. |
| D10 | The steps are four routes: `src/app/(tabs)/(beranda,perangkat,saran)/impor/[step].tsx` with `step` in `berkas`, `pemetaan`, `pratinjau`, `hasil`. | D11 | The draft lives in `ImportDraftProvider`, mounted in `src/app/_layout.tsx` inside `NavigationContextProvider`, so it survives leaving S10, tab switches and the per-tab stacks. It binds to the workspace's site: on a different site or no workspace it drops the preview, answers and commit intent and keeps the source (file or text). | Handoff S02: "Import cancel returns here without losing draft". | D12 | On web only, `draft-store.ts` mirrors the draft to `sessionStorage['hematdaya.import-draft.v1']`: site ID, source (`{ kind: 'file', name }` or `{ kind: 'paste', text }`), answers, import ID and commit intent. ### Error behaviour by code

| Call | Code | Screen behaviour |
|---|---|---|
| Preview | `IMPORT_INVALID` (400) | Stays on the step. `HDErrorSummary` lists every `details[].msg`, with the line from `loc[2]` when `loc` is `["file", "line", N]`, each linked to the file control or paste field. Status: "Berkas belum dapat diperiksa", message, reference. Source and answers kept. No **Coba lagi** (not retryable). |
| Preview | `IMPORT_TOO_LARGE` (413) | Same, with `details[0].msg` ("Ukuran 10,1 MiB melebihi batas 10 MiB." or "150001 baris data melebihi batas 150.000 baris."). A picked file whose reported `size` is over 10,485,760 bytes is refused before upload with "Ukuran {name} melebihi batas 10 MiB.", and a paste longer than 10,485,760 characters likewise. When the picker reports no `size`, the file is uploaded and this row's response decides. |
| Preview | `VALIDATION_FAILED` (422) | Summary from `details[].msg`; an item whose `loc` has `interval_minutes` and a stream key links to that minutes field. |
| Preview | `NOT_FOUND` (404) | The mapping named an asset that is no longer active. Clears `asset_map`, keeps other answers, shows "Perangkat yang dipilih tidak ditemukan lagi. Pilih ulang perangkatnya.", the message and reference. |
| Preview | `BAD_REQUEST` (400) | Message and reference. The client never sends file and text together, so this is a defect if seen. |
| Preview | `SESSION_EXPIRED`, `UNAUTHORIZED` | `end('expired')`, then the no-workspace state with `SessionEndedNotice`. Source kept. |
| Preview | `NETWORK_UNREACHABLE`, any 5xx, `UNEXPECTED_RESPONSE` | "Berkas belum selesai diperiksa", message, reference when present, "Data yang tersimpan tidak berubah.", **Coba lagi** when `recovery.retryable` (D4). The step's primary action stays available as a new attempt. |
| Commit | `IMPORT_ACK_REQUIRED` (409) | Summary linked to the checkbox (D20), message, `details[0].msg`, reference. Intent dropped. |
| Commit | `IMPORT_BLOCKED` (409) | Re-reads `GET /imports/{id}` and shows its `block_reasons` in the blocked notice; confirm disabled with reason. Message and reference. Intent dropped. |
| Commit | `IMPORT_STALE` (409) | "Pratinjau sudah tidak berlaku", message, `details[0].msg`, reference, primary **Buat pratinjau baru**, which re-posts the same source and answers (or asks to reselect a file, D12). Intent dropped. |
| Commit | `CONFLICT` (409) | Message and reference. Intent dropped, so the next **Konfirmasi impor** uses a new key. |
| Commit | `NOT_FOUND` (404) | "Pratinjau sudah tidak tersedia", message, reference, **Buat pratinjau baru**. |
| Commit | `VALIDATION_FAILED` (422) | Message, `details[].msg`, reference; intent dropped. A defect if seen, because the key is generated to the pattern. |
| Commit | `SESSION_EXPIRED`, `UNAUTHORIZED` | `end('expired')`. |
| Commit | Anything else, `NETWORK_UNREACHABLE` and `UNEXPECTED_RESPONSE` included | `unknown` (D5), then D6. |
| Status check | Any failure | Stays `unknown`: label "Status impor belum dapat diperiksa", message, reference, **Periksa status** again. |

## States

### Berkas (step 1)

| State | When | Shows |
|---|---|---|
| Workspace loading | `status === 'loading'` | "Memuat ruang kerja…" |
| No workspace | `workspace === null` | "Belum ada ruang kerja", `SessionEndedNotice`, **Mulai ruang kerja**, kept content, no import request (D33) |
| Empty | No source | Requirements notice, **Pilih berkas CSV**, paste field, examples, primary **Periksa berkas** |
| File chosen | `source.kind === 'file'` | "Berkas: {name}", **Ganti berkas**, **Hapus berkas**, the reselect sentence on web |
| Pasted | `source.kind === 'paste'` | The text, its draft note |
| Needs reselect | Web reload with a stored file | Notice naming the file, **Pilih berkas lagi**; no claim that it was recovered |
| Text dropped | Web reload after a quota failure | Notice asking to paste again |
| Checking | Preview pending | Primary loading "Memeriksa berkas…", inputs read-only |
| Refused or failed | Preview error | Per the Error table, content kept |
| Earlier import open | Draft holds a pending, unknown or confirmed commit | Notice with **Buka pratinjau** or **Lihat hasil** (D30) |

### Pemetaan (step 2)

| State | When | Shows |
|---|---|---|
| Ready | A preview exists | File line, columns, timezone, one row per stream, one control per question, primary **Lihat pratinjau**, **Ubah berkas** |

| No preview | Opened by address with no draft | Redirect to `berkas` |

| State | When | Shows |
|---|---|---|
| Committable | `blocked === false` | `HDImportPreview` with counts, period, assumptions, row errors, confirmation sentence, primary **Konfirmasi impor** |

| No preview | Opened by address with no draft | Redirect to `berkas` |
