# Mobile Standards

Expo, React Native, TypeScript, Expo Router, Android, iOS and web from one codebase.

## Layout

```
applications/<mobile>/
├── src/app/          # Expo Router routes only: compose, do not hold logic
├── src/api/          # client, failure parsing, generated contract
├── src/components/   # reusable UI
├── src/features/     # feature logic and screens
└── tests/            # screen and flow tests; unit tests may sit beside their module
```

## Code

- TypeScript strict. No `any`; narrow `unknown` at boundaries.
- Import through `@/`. No deep imports from `react-native/Libraries/*`.
- Add native packages with `npx expo install` so versions match the SDK.
- Every `EXPO_PUBLIC_*` value ships in the bundle: never put a secret there.
- `src/api/schema.generated.ts` is generated by `make generate-api`. Never edit it.

## Server contract

- The service owns business rules and calculations. The client renders what it receives.
- Branch on the public error `code`, never on message text. Show `message` and the reference ID.
- Honor `recovery`: stop retrying when `retryable` is false or `max_attempts` is reached.
- Every request has a timeout. Mutations that may be retried carry an idempotency key.

## Screens

- Every screen has loading, success, failure and empty states. A failure keeps the last confirmed content visible.
- Touch targets are at least 48 × 48. Use `accessibilityRole`, `accessibilityLabel` and `accessibilityState`.
- Respect font scaling: never set `allowFontScaling={false}`. Long text wraps.
- Use safe areas and keep the active field and primary action above the keyboard.
- Announce status changes with `accessibilityLiveRegion` or `AccessibilityInfo`.

## Testing

- Jest with `jest-expo` and React Native Testing Library. `make check` enforces 80% line coverage.
- Query by role and visible text. Assert behavior, including failure and retry paths.
- A browser check does not prove native behavior. Record which runtime was actually exercised.
